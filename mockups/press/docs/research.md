# Исследование сценариев и обоснование UI

Дата: 27 октября 2026. Метод: desk research по первичным источникам + проверка
контрактов Blog Engine/Identity. Пользовательские интервью и usability-тестирование
с реальными читателями не проводились; гипотезы дизайна не выдаются за их результат.

## Выводы из источников

| Паттерн | Наблюдение и источник | Решение в прототипе |
| --- | --- | --- |
| Тематическое открытие | Ghost использует tags для группировки и тематических архивов. [Ghost: Tags](https://ghost.org/help/tags/) | Темы в навигации, category/tag collections, кликабельная классификация. Фильтры соответствуют Blog: любая категория и все выбранные теги. |
| Работа автора | Единая область материалов и статусы упрощают подготовку публикаций. [Ghost: Organizing content](https://ghost.org/help/organizing-content/) | Редакция с All/Draft/Published, первичным CTA «Новый материал», ясным статусом каждой строки. |
| Предпросмотр | Подготовка включает просмотр результата перед публикацией. [Ghost: Publishing](https://ghost.org/help/publishing-content/) | Режимы «Текст / Предпросмотр» и отдельное подтверждение publish. Расписание Ghost не переносится: у Blog его нет. |
| Настройки материала | Slug и классификация связаны с подготовкой материала. [Ghost: Post settings](https://ghost.org/help/post-settings/) | Отдельный inspector справа; permanent slug locked после первой публикации; Published edits предупреждают о немедленном изменении public text. |
| Контекст разговора | WordPress поддерживает древовидные ответы. [WordPress: Comments](https://wordpress.org/documentation/article/comments-in-wordpress/) | Inline reply composer, раскрываемые ветки, локальный контекст родителя. На телефоне отступы ограничены, связь сохраняется. |
| Пагинация обсуждений | Корневые страницы и глубина обсуждения — разные настройки. [WordPress: Discussion settings](https://wordpress.com/support/discussion-settings/) | Независимая подгрузка корней и прямых ответов. Depth 5 и placeholders согласованы с Blog, целое дерево не запрашивается. |
| Модерация | Список комментариев должен давать контекст и действия. [WordPress: Comments screen](https://wordpress.org/documentation/article/comments-screen/) | Экран с publication/state filters, private Hidden text и hide/restore. Нет выдуманных Pending/Spam/Trash и approve queue. |
| Чтение длинного текста | W3C в AAA Visual Presentation описывает ограничение строки, интерлиньяж и отказ от justified text. [W3C: Visual presentation](https://www.w3.org/WAI/WCAG21/Understanding/visual-presentation) | Колонка чтения до 700 px, текст 18 px, line-height 1.85–1.9, спокойные заголовки и цитаты, derived оглавление. Это ориентир дизайна, не заявление о полной WCAG-сертификации. |
| Обратная связь форм | Ошибка должна объяснять способ исправления. [W3C: User notifications](https://www.w3.org/WAI/tutorials/forms/notifications/) | Постоянные labels, field errors и общий alert, сохранённый ввод; version conflict сравнивает версии без overwrite. |
| Доступная авторизация | Password managers и подходящие autocomplete снижают нагрузку. [W3C: H100](https://www.w3.org/WAI/WCAG21/Techniques/html/H100) | username/current-password/new-password, показ пароля, paste разрешён, никаких выдуманных требований «обязательно цифра+символ». |
| Цели нажатия | WCAG 2.2 задаёт требования к размеру/разнесению интерактивных целей. [W3C: Target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | Основные кнопки 44–48 px, фокус, видимые hover/disabled, доступные имена icon buttons и работа диалогов с клавиатуры. Компактные вторичные controls требуют проверки в реальном accessibility audit. |

## Четыре основных journey

**Читатель.** Увидеть интересный материал → прочитать → перейти в близкую тему →
при желании войти → поддержать или ответить. Главная открывается без auth wall.
У неё выраженная визуальная иерархия, а вход остаётся вторичным действием.

**Автор.** Найти черновик → написать → настроить описание/slug/классификацию →
предпросмотр → явное publish. Сохранение не маскируется под публикацию.
Для Published видно предупреждение: отдельной staging-редакции backend не даёт.

**Модератор.** Увидеть контекст → скрыть конкретный узел → сохранить путь к
видимым ответам → при необходимости вернуть текст. Admin-only destructive
действия отделены от полномочий Moderator.

**Участник.** Войти/зарегистрироваться → подтвердить адрес → настроить собственное
displayName → контролировать пароль и сеансы. Ошибки login и письма не позволяют
определить существование аккаунта. Deactivate объясняет необратимость и сохранение PII.

## Визуальная концепция

«Слой» — редакционный журнал о внимательном взгляде на повседневность. Серийная
типографика заголовков и цитат задаёт темп чтения, нейтральный sans-serif обслуживает
навигацию/формы. Фотография — часть композиции, а не фон для всего интерфейса.
Полоса тем и сетка материалов создают ритм без перегруженного dashboard на главной.

Журнал и кабинет используют общие семантические цвета и controls, но разные
плотность и структуру. Editor убирает лишнюю навигацию, account shell сохраняет
ощущение того же продукта. Desktop/tablet/mobile используют один набор компонентов.

Default brand: тёплый белый + шалфей + интерьерная фотография. Forest и Midnight
проверяют переносимость дизайн-системы на другой цвет и изображение без переписывания UI.

## Границы исследования

Не скопированы неподдержанные возможности продуктов-референсов. В частности,
счётчики reading time/TOC получаются локально из Markdown, а имя/аватар автора не
берутся из собственного Identity profile. Публичные авторы обозначены локальной
ссылкой «Автор · 0001». UI не обещает search, scheduling, uploads или подписки.

Технологический выбор: React + TypeScript + Vite для локального SPA-прототипа,
React Router для маршрутов. [React: Build from scratch](https://react.dev/learn/build-a-react-app-from-scratch),
[Vite: Getting started](https://vite.dev/guide/). Собственные небольшие controls
использованы для цельного визуального языка; Ant Design не требуется для этого объёма.

Identity отдельно сверён с `D:/Space/Personal/identity-service`, commit `43dabc6`,
совпадающим с project-local интеграционной спецификацией. Ни production-доступ,
ни настоящие credentials при проектировании не использовались.
