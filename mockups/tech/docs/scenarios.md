# Карта сценариев и экранов

Основание: `specs/001-blog-engine-mvp/spec.md`, `docs/api/frontend-api-spec.md`, точный REST snapshot Identity 1.1.0 из навыка identity-integration. Все переходы локальные, операции исполняются над тестовыми данными.

## Чтение и участие

| Экран | Сценарии и состояния |
| --- | --- |
| `/` | Свежее / популярное за всё время, ANY категорий и ALL тегов, первые 4 карточки и подгрузка ещё 4, повтор загрузки следующей страницы |
| `/topics` | Направления и список тегов |
| `/category/:slug`, `/tag/:slug` | Тематическая лента, фильтры и сортировка, 404 неизвестного направления |
| `/search?q=` | Локальный поиск по заголовкам и описаниям, пустой результат, изменение запроса |
| `/bookmarks` | Сохранить/убрать из ленты и статьи, список, пустое состояние; в пределах вкладки |
| `/authors/:authorId` | Имя и опубликованные материалы тестового автора; неизвестный автор → 404 |
| `/posts/:slug` | Markdown/GFM без raw HTML, оглавление, время чтения, автор, лайк/отмена, просмотр с дедупликацией 24 ч, закладка, копирование ссылки |
| `#comments` | Корни по 3, ответы по 2, до 5 уровней; добавление корня/ответа, редактирование своего, подтверждение удаления; заглушки скрытого/удалённого родителя; вход для гостя |
| `/comments/:id/manage` | Приватный контекст своего скрытого комментария: изменять нельзя, удалить можно; Admin может изменять допустимый текст |
| `/about` | Проект, правила обсуждения, переход к регистрации |
| `*` | 404: материал/страница не найдены, возврат в ленту |

Закладки, поиск и подборка автора — локальные UX-расширения без обещания новых API MVP. Обычный посетитель не видит черновики и скрытый текст комментариев. Скрытие не раскрывает автора. После удаления родителя сохраняются доступные потомки.

## Рабочее место автора

- `/workspace`: свои материалы; для Admin — все. Всё / опубликованные / черновики, счётчики, редактирование, подтверждение удаления.
- `/workspace/new`, `/workspace/:id/edit`: заголовок, slug, описание, Markdown, HTTPS-обложка, категории до 5, теги до 20. Сохранение, предпросмотр, публикация с подтверждением, снятие с публикации, удаление.
- После первой публикации slug фиксирован. Изменение Published сразу попадает в публичную версию; отдельного отложенного черновика нет.
- Несохранённый текст защищён подтверждением ухода и beforeunload.
- Конфликт версии открывает сравнение локального и актуального текста; автоматической перезаписи нет.
- Reader не получает права автора при входе/регистрации. Чужой материал Author редактировать не может.

## Модерация и справочники

- `/moderation`: опубликованные и изменённые комментарии, фильтры по состоянию и материалу, скрытие и восстановление. Это постмодерация: предварительного одобрения нет. Удалённый текст восстановить нельзя.
- Moderator не переписывает и не удаляет чужой комментарий. Admin имеет дополнительные действия редактирования и удаления.
- `/admin/taxonomy`: категории / теги, создание, переименование, удаление. Используемая запись не удаляется до снятия назначений; показывается объяснение. Дубликат/конфликт версии отображается в форме.
- Локальные роли не назначаются через HTTP и не редактируются в этих экранах.

## Identity — входы и восстановление

| Route | Моделируемый HTTP-контракт | Переходы |
| --- | --- | --- |
| `/auth/login` | POST `/api/v1/auth/login` | Успех → безопасный локальный returnTo либо лента; generic неверные данные; 429; недоступность |
| `/auth/register` | POST `/api/v1/auth/register` | Необязательное имя, email, пароль и повтор; generic accepted → письмо; автоматического входа нет |
| `/auth/check-email` | Состояние после 202 | Нейтральное сообщение: не подтверждает существование аккаунта и доставку письма |
| `/auth/resend-verification` | POST `/api/v1/auth/email/verification-request` | Нейтральный ответ; cooldown повторного письма |
| `/auth/verify-email` | POST `/api/v1/auth/email/verify` | Подтвердить → успех → вход; недействительная ссылка → повторное письмо |
| `/auth/forgot-password` | POST `/api/v1/auth/password/forgot` | Email → generic accepted; не раскрывает наличие аккаунта |
| `/auth/reset-password` | POST `/api/v1/auth/password/reset` | Новый пароль и повтор → успех → вход; просроченная/использованная ссылка → новый запрос |
| `/auth/accept-invitation` | POST `/api/v1/auth/invitations/accept` | Новый пароль → активация приглашённого → вход; недействительная ссылка |
| `/auth/session-expired` | Ошибка/отзыв сессии | Повторный вход |
| `/auth/deactivated` | Результат деактивации | Сеансы завершены, публичного восстановления нет, переход к ленте |

## Identity — личный кабинет

| Route | Контракт | Сценарии |
| --- | --- | --- |
| `/account/profile` | GET/PATCH `/api/v1/users/me` | Имя до 120 символов, очистка имени; email read-only, статус подтверждения, локальные роли |
| `/account/security` | POST `/api/v1/auth/password/change` | Текущий + новый пароль + повтор, валидация, отзыв всех сеансов и возврат ко входу |
| `/account/sessions` | GET `/api/v1/sessions`, DELETE `/api/v1/sessions/{id}` | Свои активные сеансы, текущий отмечен, завершение отдельного, пустой список; logout-all с подтверждением |
| Меню → выйти | POST `/api/v1/auth/logout` | Гость → лента |
| Все сеансы | POST `/api/v1/auth/logout-all` | Подтверждение → все сеансы завершены, текущий тоже |
| `/account/deactivate` | POST `/api/v1/users/me/deactivate` | Текущий пароль, согласие с последствиями, подтверждение; это терминальная деактивация, а не удаление ПД |

Пароль 15–128 Unicode code points после NFKC, с лимитами UTF-8; пробелы не обрезаются, искусственных требований к классам символов нет. На входе более сильная политика регистрации не применяется к существующему паролю. Реальная denylist и проверка текущего пароля находятся на сервисе; макет их не заменяет.

Фрагмент `#token=` читается только в память и сразу убирается из адреса. `?demo=valid` позволяет показать действительную ссылку без токена. Refresh не имеет отдельной страницы: в production координируется на BFF, а отказ переводит в session-expired. JWKS и административная Identity Console не относятся к пользовательским экранам блога. Социального входа, MFA, passkeys, смены email и публичной реактивации в контракте нет.

## Сквозные состояния

Кнопка «Прототип» и `/prototype`: нормальное состояние, skeleton, пустая коллекция, offline, 503, конфликт версии, неверные данные/ссылка, 429 с ожиданием, ошибка следующей страницы. Защита закрытых экранов: гость → вход, недостаточная роль → 403 с возвратом в ленту, неизвестный/непубличный материал → одинаковый 404. Формы сохраняют введённый текст при ошибке. Для опасных действий используются диалоги, в остальных случаях — inline feedback/toast.
