# Исследование сценариев блогов

Дата: 27 октября 2026. Метод: desk research официальной справки Хабра и DEV Community; анализ локальных спецификаций и трёх предоставленных референсов. Это анализ интерфейсных паттернов, а не интервью или проверка гипотез на реальных пользователях.

## Источники и наблюдения

1. [Хабр: лента](https://habr.com/ru/docs/help/lenta/) — разделение свежего и популярного, тематические хабы, постепенный переход от общего потока к теме. В нашем контракте есть recent и popular за всё время; временные периоды, рейтинговые пороги и подписки не добавляем.
2. [Хабр: публикации](https://habr.com/ru/docs/help/publications/) — явная кнопка написания, тематизация, Markdown, предпросмотр, закрытые черновики. Берём последовательность подготовки текста; доступ автора определяется локальной ролью вместо кармы.
3. [Хабр: комментарии](https://habr.com/ru/docs/help/comments/) — обсуждение привязано к материалу. В проекте реализуем дерево согласно собственному контракту: отдельная подгрузка корней и ответов, пять уровней, заглушки скрытого/удалённого родителя.
4. [DEV: writing, editing and scheduling](https://dev.to/help/writing-editing-scheduling) — сохранение черновика и возвращение к нему через dashboard; заголовок, тело, обложка, теги, явная публикация. Планирование и серии встречаются в продукте, но в нашем MVP отсутствуют.
5. [DEV: Following tab](https://dev.to/devteam/new-dev-feature-following-tab-5fae) — полезность различения общего потока и персонального. Для MVP персонализация ограничена локальными закладками: сервис подписок отсутствует.

## Основные задания посетителя

| Задание | Маршрут | Принятое решение |
| --- | --- | --- |
| Найти полезный опыт | Лента → тема/тег → статья | Понятные названия категорий, автор, короткое описание, время чтения |
| Выбрать из большого потока | Свежее / Популярное → фильтры | Популярное по лайкам за всё время, категории ANY, теги ALL |
| Прочитать без отвлечений | Статья → оглавление → обсуждение | Колонка чтения, липкое оглавление, подписи у действий |
| Вернуться к материалу | Закладка → сохранённые | Мгновенный отклик, возможность отмены; локальное UX-расширение |
| Обсудить ремонт | Статья → вход → комментарий/ответ | Вход сохраняет адрес статьи; комментарии обычным текстом |
| Поделиться опытом | Материалы → черновик → preview → публикация | Раздельные сохранение и публикация, проверка полей, подтверждение |
| Исправить/снять текст | Материалы → редактирование → сохранить/снять | Опубликованные изменения видны сразу, slug после первой публикации фиксирован |
| Поддержать обсуждение | Модерация → скрыть/вернуть | Нет премодерации, сохраняем чужие ответы, ограничения Moderator/Admin |
| Вернуть доступ | Вход → forgot → письмо → reset → вход | Нейтральные сообщения о письмах, новый пароль завершает сеансы |
| Контролировать аккаунт | Профиль → безопасность → сеансы | Неизменяемый email, отзыв конкретной сессии и всех сессий, явные последствия деактивации |

## Архитектурные решения

Лента — основной продукт, hero занимает один короткий экранный блок. На внутренних страницах hero не повторяется. Карточка раскрывает больше контекста, чем сеточная плитка: это уместно для технических рассказов с подробными обложками. Правая колонка поддерживает чтение: популярные статьи, теги, краткая заметка.

Персональные рабочие экраны используют более компактную функциональную сетку. Отдельные входы для автора, модератора и администратора зависят от роли. Назначения ролей через UI нет: этого не поддерживает backend.

Поиск по заголовкам/описаниям, закладки и страницы авторов сознательно выделены в документации как композиция локальных данных. Внешних API и вымышленных production-возможностей нет. Каталоги моделей, запчастей, мероприятия, барахолка, форум, подписки, уведомления и социальный вход не входят в реализацию.

## Что проверять с пользователями дальше

1. Замечают ли люди различие между сохранением черновика и публикацией?
2. Достаточно ли описания и обложки для выбора материала без уровня сложности?
3. Находят ли переход к обсуждению и отличают ли скрытый комментарий от удалённого?
4. Удобно ли пользоваться тегами и длинными ветками на телефоне?
5. Понятно ли, почему новый аккаунт не получает права автора автоматически?

В шапке после ревью добавлена локальная демонстрация ответов на комментарии под колокольчиком. Сервер уведомлений не реализован и в контракт MVP не добавлен. Generic-презентация использует визуальные ориентиры официальных [Ant Design tokens](https://ant.design/docs/react/customize-theme/) и [Layout](https://ant.design/components/layout/); пакет antd в этой реализации не используется.
